# simpleppt

网站：https://chengyulian0228-debug.github.io/yejian/

把重复标题的 PDF 课件整理为连续复习讲义。暖白与暗红配色，支持电脑、平板和手机。

## 使用

1. 选择 PDF（100 MB 以内），或先试用网页内生成的示例。
2. 选择均衡、紧凑或留白版式，以及原页眉、主色或纯正文风格。
3. 默认开启本地视觉筛图，首次下载约 154 MB 开源 CLIP 模型并缓存。可选择 HF Mirror 国内镜像或 Hugging Face 官方源，关闭后仅做基础清理。更多设置可指定页码范围、来源显示方式。
4. 整理后点“检查图片”，核对所有独立图片及删除理由，可补删或恢复，再按选择重新生成。也可对比预览、下载 PDF，在阅读器中高亮或批注。
5. 需要解题时，打开“题目助手”：读取指定原 PDF 页面的文字，或手动粘贴题目；核对后复制“题目＋提示词”，到自己使用的 AI 工具中粘贴发送。支持完整解析或先给提示，也可补充课件参考材料。对比预览和历史讲义中也能从当前原页进入。

课件不上传服务器，不调用付费 AI 接口。本地图片分类使用 Transformers.js、ONNX Runtime 与量化 CLIP，运行于浏览器 Web Worker；正文不做 AI 改写。PDF.js 在本地读取 PDF；pdf-lib 和嵌入的开源 Noto Sans SC 字体在本地输出 PDF。首次使用需要从网站加载程序、字体、PDF.js 和 ONNX Runtime 资源；开启视觉筛图时另从所选模型源下载模型权重，不向模型源发送图片或课件。不要将“本地处理”理解为首次打开也不需要网络。

题目助手只读取文字和复制提示词，不生成答案、不自动打开或发送给外部 AI，不需要 API Key。用户自行粘贴后，所选 AI 服务才会收到粘贴的内容，费用和使用规则由该服务决定。读题按原 PDF 页码，一次最多 20 页；扫描题和图片、复杂公式须对照补充，不能保证所有版面下的文字顺序。再次读页会追加到已有题目；关闭助手后草稿不保存。自动复制不可用时提供选中文本手动复制。

历史记录和文件存入当前浏览器的 IndexedDB，不跨设备同步。清除网站数据或点击“清空本机记录”后记录消失；请及时下载重要讲义。关闭页面会中断未完成的整理。手机内存不足时，可在更多设置中分段整理。

## 整理边界

- 按可识别的标题编号恢复层级，同一路径的重复标题只排一次。
- 仅合并同一标题路径下完全重复的段落；保留新增条件、数字和说明。
- 正文不做语义改写或摘要。通用规则无法判断所有教师的结构，生成后应对照预览。
- 自动比较图片外观、位置、附近图注与推广文字，清理跨页重复的边角装饰、小型边角徽标，以及有明确推广文字的图片。重复本身不足以删除正文图表；扫描页、大图、带图注或叠加文字的图、公式遮罩及用途不明确的图片保留。基础清理采用本地规则。默认开启的本地 CLIP 进一步检查普通正文配图，区分装饰性卡通、普通照片、标志与流程图、图表、文字截图、题图、教学参考图；有清晰装饰性分数优势时建议删除，不能保证判断图片与任意课程的知识关联。带明确图注、叠加文字、公式遮罩和整页扫描图优先保护。结果中显示实际运行模型的图片数和移除数，支持逐图恢复或补删并重新生成。整页截图内部或纯矢量配图尚不能单独识别删除。模型加载失败会明确报错，不静默退回基础模式。
- 普通图文页将独立图片裁出并插入可搜索正文，避免一张装饰图导致整页原样保留。扫描页、叠加图文、复杂矢量页、多栏页及缺少字体字形的页面保留整页原图，并在渲染时跳过已确定的装饰图片绘制指令。这些页面可能仍带原标题，且图片中的字不能直接选择。此版本不含 OCR。
- 默认隐藏原 PDF 来源页码，可选书签、文末对照或正文显示。
- 自动清理不同页面底部固定位置重复的小号署名，不增加设置入口；姓名须能作为文字读取，且与正文隔开。原图保留页也会遮去已识别的署名。正文姓名、仅出现一次的署名和无法读取的图片署名保留；纯图片署名不含 OCR，不能保证识别。
- 采用开源中文字体近似原字体；“保留原页眉”截取原页顶部并清理可识别的大标题和已识别的装饰图片，不能保证复原所有模板。

## 本地开发与检查

需要 Node.js 22.13+（推荐 24）。

```sh
npm ci
npm run dev
npm test
npm run build
node scripts/serve-static.mjs
```

最后一个命令只提供 `dist`，并在 `http://127.0.0.1:4173/yejian/` 模拟 GitHub Pages 的项目子路径。公开网站不需要 Python。

## GitHub Pages 发布

1. 新建一个空的公开仓库（建议名称 `yejian`）。上传本发布包的源码，不要上传个人课件、历史或开发缓存。
2. 仓库 Settings → Pages → Build and deployment → Source 选择 **GitHub Actions**。
3. 推送到 `main` 后，`.github/workflows/pages.yml` 会安装依赖、测试、构建并发布。
4. 等待 Actions 成功，打开该部署显示的地址，通常为 `https://用户名.github.io/yejian/`。

配置使用相对资源地址，支持任意仓库名称。GitHub 免费账号通常需使用公开仓库发布 Pages；仓库中仅包含网站代码及开源字体。访客的课件不会进入仓库。

## 依赖与字体授权

Noto Sans SC 来自 [noto-cjk](https://github.com/notofonts/noto-cjk)，采用 SIL Open Font License 1.1，见 `public/fonts/OFL.txt`。PDF.js、pdf-lib、fontkit、React、Vite、Lucide 等依赖遵循各自许可证；构建资源附带对应许可证。网站不使用远程字体、分析统计、第三方上传接口或远程推理 API。模型采用 Xenova/clip-vit-base-patch32（MIT），固定修订 6b7c523703ae26e39be4b03774966f8571c7f523；Transformers.js 遵循 Apache-2.0，ONNX Runtime 遵循 MIT。模型只做零样本图片类型分类，其分数并非知识关联的准确概率。下载源可获取常规网络请求信息，但不会接收课件。模型缓存与讲义历史分开，清空讲义历史不会清空模型缓存。

`backend/`、`serve.py` 和 Python 测试属于旧本机版，仅留在原工作区作参考，不进入静态发布包。
